# Reusable Open Lovable generation on AI BOX

## Purpose

This is the durable handoff for approved ChatGPT Projects that need a new website seed generated by the Open Lovable capability on AI BOX. The consuming Project does not operate AI BOX manually.

All execution follows:

`ChatGPT -> GitHub -> AI BOX Controller -> AI BOX`

## Controller request

Create an issue in `gnomedev-gvs/aibox-control` with a title beginning `[AIBOX]` and this JSON body:

```json
{
  "schema": 1,
  "action": "open-lovable-generate",
  "project": "open-lovable",
  "target_project": "<managed-project-alias>",
  "generation_slug": "<lowercase-seed-slug>",
  "generation_prompt": "<website generation brief>"
}
```

`target_project` must already exist in the AI BOX managed fleet. `generation_slug` is 1-48 lowercase letters, numbers or internal hyphens. `generation_prompt` is required and is capped at 8,000 characters.

## What the controller does

The action is a heavy, serialized Open Lovable job. It:

1. Requires production Open Lovable health with Codex, local Docker sandbox and generation readiness green.
2. Creates an ephemeral hardened local Docker sandbox.
3. Applies a governed prompt that forbids new external npm packages, remote scripts, analytics, credentials, secrets, placeholder copy, lorem ipsum and external image dependencies.
4. Generates React/Vite/Tailwind source through the production Codex integration.
5. Applies the generated source to the sandbox.
6. Runs the generated Vite production build.
7. Renders the private preview in Chrome and requires a real HTML body plus a non-trivial screenshot.
8. Exports the generated project archive.
9. Rejects unsafe archive paths, symlinks, oversized archives, excessive file counts and excessive expanded size.
10. Writes the validated seed only to a new isolated branch in the target repository.
11. Destroys the ephemeral sandbox in the final cleanup path.

## Output contract

Successful output is stored at:

`.open-lovable/seeds/<generation_slug>`

on a new target-repository branch named:

`open-lovable/<generation_slug>`

The controller does not merge the seed into the target repository's default branch. It also refuses the AI BOX Controller and Open Lovable source repositories as generation targets.

The result records the target repository, branch, seed path, commit, exported file count, generated build result, browser result, screenshot size, sandbox provider and AI provider.

## Consuming Project responsibilities

Open Lovable supplies a validated starting implementation, not automatic production approval. The consuming website/client Project remains responsible for business content, creative direction, brand assets, routing requirements, client-specific functionality, accessibility review, responsive review, security review, final tests and deployment.

Before merging a generated seed, the consuming Project must review the isolated branch, remove unnecessary generated cruft, verify all content and interactions, run its normal repository tests/builds, and follow that Project's own promotion workflow.

## Failure and retry behaviour

Generation fails closed. A failed build, browser check, unsafe archive, invalid target, pre-existing output branch, application error or sandbox-cleanup failure prevents a successful result. Do not bypass the controller or copy sandbox files manually. Diagnose through the controlling GitHub issue and retry only after the underlying fault is understood.

## Platform ownership

The Open Lovable Integration Project owns the generator platform, AI provider integration, sandbox architecture, controller action, platform validation, upgrades and recovery procedures. The consuming website/client Project owns the generated website after the validated seed is handed off.
